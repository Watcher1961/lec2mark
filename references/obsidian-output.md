# Obsidian 输出约定

生成 Obsidian 笔记文件时读取。本文件只规定组织、语法和交付；概念教学顺序仍以 SKILL.md 为准。示例中的路径和内容是格式演示，只有实际生成或存在时才能使用对应链接。

## 文件组织与可移植性

本地 Obsidian 课程笔记默认沿用用户已有课程的扁平结构；用户另有要求时以用户为准。用户要求参照其他课程时，只读其指定 vault 内少量代表性总览、周正文、词典及速查文件，先确定组织与命名，再整理目标课程，不改参考课程。

```text
课程目录/
├── 课程代码 课程名称.md
├── 课程代码 Week1 教学主题.md
├── 课程代码 Week2 教学主题.md
├── 课程代码 专有名词词典.md
└── 课程代码 公式速查与复习清单.md  # 按需
```

采用按周结构时，每个已授课 Week 一份主正文；同周多个来源融合，同一课件跨周按实际进度分开。用户确认的当前周次是上限，不能从课件编号猜周次。用户明确要求预习或整理后续范围时可另行生成并标明预习；否则未授课资料可在总览简述状态，不另生成完整“week 待定”章节；已有预整理在用户要求精简目录时按授权范围合并或移除，遵循用户的备份与恢复约定。

用户明确要求合并 Concepts 时，在授权范围内将其内容整合到一份词典的概念辨析章节，保留有用的定义、条件、实例与辨析；详细推导链接周正文，不能只保留术语列表而丢掉原有内容。公式速查附使用条件和正文入口，不替代教学主线。

不为完整模板自动创建 Concepts、README、Rules、Sources 或来源映射文件。出处、教师补充、勘误与待核实内容放在相关周正文或脚注；工作用索引、抽取稿及检查记录只在处理期间存放于课程输出目录之外的授权工作位置，工作流结束前删除。备份与恢复方式遵循用户约定；未经授权不删除原有内容。执行用户授权的合并、改名或移除时，同步更新目标范围内的引用。稳定文件名可作为新文件 aliases，减少已有 wikilink 断裂；不要用重复入口文件替代修复导航。

附件策略沿用用户现有 vault 约定；没有约定时不自动新增附件目录，需要随附图片时按实际用途和用户要求确定位置。删除已有附件时同步清理或替换失效图片引用，不擅自删除本次范围之外的已有附件。可用原 PDF 的文件名和物理页码定位；原文件可访问且用户采用本机 vault 时，可像现有课程一样直接链接原文件及 `#page=N`，含空格路径用 `<...>` 包住。图像支持的推理仍需写入正文，可用原生 Mermaid 或文字解释；移除图片不等于跳过来源视觉核对。用户要求可整体迁移时，采用相对路径或纯来源定位，说明原文件依赖；用户明确要求随附图片时按需保留，图片名应区分课程、章节和来源。处理时用于视觉核对的临时页面图放在 vault 外的授权工作位置，不复制进课程笔记目录，工作流结束前删除。

单主题可只交付一份笔记；周次未确认时按主题命名，不虚构 Week。总览说明学习顺序、先修关系与原章节对应，不能只列文件名。未指定 vault 时交付可整体导入的文件夹，不搜索其他 vault。

用户给定 vault 路径时只改目标课程，不更改 `.obsidian` 设置或安装插件。课程内部使用可解析的 wikilink 或相对 Markdown 链接；同名时明确 vault 内路径。别名放在表格中需转义 `\|`。不为未生成章节创建空链接，也不把工作目录当作固定 vault 根路径。

## 文字、公式和代码

使用清晰标题、短段落与带语言标记的代码块。行内公式用 `$...$`，独立公式的开始与结束 `$$` 各占一行；多步推导可用 `aligned`。长推导和多行代码不要放进表格。公式中的对象、维度、单位和成立条件仍应在正文解释，排版正确不代表数学正确。

代码块明确语言；未知语言用 `text`。与源码对应的解释注明文件和函数，不假定 Obsidian 能跳转任意源码行。长示例可节选，但需要的上下文、输入和输出不能被删成无法理解的片段。

YAML 属性可记录 `title`、`tags`、`sources`，不为凑模板增加未知字段。列表值保持类型一致，含冒号或 wikilink 的字符串用引号包住。页面中的课件出处与实际引用范围分开：`sources` 列表不能代替段落定位。

## 关联、出处与折叠答案

跨章引用用 `[[笔记名#标题|显示文字]]` 或相对 Markdown 链接；除了链接，写一句“这里为什么需要它”。wikilink 放在表格中时处理别名分隔符的转义，或改用不带别名的链接，避免破坏列结构。目标文件及标题必须能解析。

出处放在论断附近或脚注中，来源类别只在有助于辨别内容时标出。不要让逐句标签打断阅读，也不要用一条章末来源覆盖所有独有补充。下面仅演示来源与补充的分界：

```markdown
课件中的结论在非零输入条件下成立。[^condition]

教师补充：先检查输入是否为零，再应用该式。[^teacher]

教学补充：把零输入代入分母，可以解释为什么必须先检查条件。

[^condition]: lecture03.pdf，文件页 12。
[^teacher]: lecture03.txt，原文件第 210–214 行；无时间戳。
```

少量使用 `> [!note]` 或 `> [!warning]` 突出教师强调与待核实内容。答案可折叠，关键推理保留在主文中：

```markdown
> [!example]- 参考答案
> 先检查公式是否满足使用条件。
>
> 如果分母为零，该式不能直接使用；回看“适用条件”中的说明。
```

折叠内容中的空行也保留 `>`。不使用需要额外插件的提示框、查询或交互语法。

## 图示与最终核对

关系或流程用 `mermaid` 代码块，节点名称简短，箭头含义在正文解释。用户明确要求随附图片时，几何、曲线和手写局部可用实际生成或提取的图片；`![[课程名-L03-p12-投影.png]]` 仅在目标唯一且随附时使用，或使用相对图片路径。说明图的来源和是否重绘，不能只交付一个无解释的截图。

静态核对实际产物的相对链接、wikilink 目标及标题、脚注定义、附件存在性、YAML 和代码围栏。跨目录检查时排除示例代码块中的演示链接。具备渲染环境时检查代表性公式、Mermaid 与折叠答案；未预览时只报告静态检查，不声称已经验证 Obsidian 显示。交付简要说明文件入口、材料覆盖、未决疑点及验证状态，不把这些执行说明混进教学主线。
